# Курсова робота: інформаційна система прокату обладнання
### Варіант №12

Клієнт–серверна інформаційна система на Java 21 для автоматизації обліку каталогу обладнання, клієнтів, заявок на прокат та договорів прокату. Завершена реалізація (Етап IV).

**Стек технологій:** Java 21, Maven, Servlet API 4.0.1, Apache Tomcat 9.x, MySQL, JDBC, Jackson, JavaFX, JUnit 5, Git.


## Структура репозиторію

```text
kpp-coursework-kostianetska-variant12/
├── .gitignore       # ігноровані файли (target/, *.war, IDE, логи тощо)
├── database.sql     # структура БД та початкові дані
├── server/          # серверна частина (моделі, DAO, Service, Servlet, тести JUnit 5)
└── client/          # JavaFX-клієнт (UI, HTTP-клієнт, фоновий імпорт)
    └── sample-data/ # вхідний CSV (equipment.csv)
```
## Запуск

1. Створити базу даних MySQL за файлом `database.sql` (база: `equipment_rental`, таблиці відповідно до структури варіанта) та за потреби задати локальні параметри підключення до БД (без збереження реальних паролів у репозиторії).
2. Зібрати серверний проєкт:
   `cd server && mvn clean package`
3. Розгорнути отриманий файл `target/equipment-rental-server.war` на сервері **Apache Tomcat 9.x**.
4. Перевірити роботу сервера через GET-запит у браузері (наприклад, `http://localhost:8080/equipment-rental-server/equipment` згідно з налаштованим маршрутом отримання даних — сервер має повернути JSON).
5. Запустити JavaFX-клієнт із каталогу `client`:
   `cd client && mvn javafx:run`

## Тестування

Автоматизовані модульні тести (**JUnit 5**) розміщені в `server/src/test/java`. Для запуску виконайте:

`cd server && mvn clean test`

Очікуваний результат: успішне проходження всіх тестів (`0` помилок, `BUILD SUCCESS`) — перевірка обчислення факторів та інтегрального показника, дозволених і заборонених переходів станів заявки та валідації моделей.

## CSV (фоновий імпорт)

- **Файл:** `client/sample-data/equipment.csv` (відносний шлях рахується від робочого каталогу `client`).
- **Кодування:** UTF-8. **Роздільник:** `;` (крапка з комою), формат полів — згідно з індивідуальним завданням.
- Імпорт виконується у фоновому режимі (`ImportEquipmentTask` у JavaFX) з відображенням прогресу та повідомленням про результат; записи додаються в MySQL через HTTP-запити до сервера, а не напряму через JDBC.
- **Увага:** не імпортуйте той самий CSV повторно без перевірки стану БД, якщо в коді не передбачено фільтрацію дублікатів.

## Основні функції (Етап IV — завершено)

- HTTP/JSON API (`Servlet`) для обладнання, клієнтів, заявок на прокат та договорів.
- JavaFX-клієнт: перегляд, CRUD-операції, редагування та валідація даних.
- Розрахунок інтегрального показника заявки за факторами `F1`, `F2`, `F3`.
- Чотиристанний життєвий цикл заявки на прокат та серверна перевірка дозволених/заборонених переходів.
- Фоновий CSV-імпорт (`ImportEquipmentTask` + індикатор прогресу + обробка помилок).
- Модульні тести JUnit 5 та журналювання подій (`Logger`).
